01 · 系統形狀

資料往前走，依賴往核心靠

Targeted 與 Untargeted 的入口、搜尋範圍和交付方式不同，但不另造一套峰判斷或跨樣本決策核心。下圖是責任順序，不代表每一種方法都執行完全相同的步驟。

從入口到完成證據

  1. GUI / CLI
    與設定    收下使用者選擇，安排工作入口。
  2. Extraction / Discovery依工作模式擷取已知目標或探索候選。
  3. Peak Detection建立峰的觀察、假設與積分證據。
  4. Alignment跨樣本整理、修復與格值決策。
  5. Output把 owner 的結果呈現為檔案，不重算證據。
  6. 完成證據
    → Inspector    只讀檢視已留下的記錄。

Configuration 提供型別化設定；applications/ 組合 Targeted 或 Untargeted 流程並管理交付。execution/ 處理排程、資源和收尾，沒有科學或 writer 決定權。

候選與單樣本證據

Discovery 產生一般候選；Extraction 協調 Targeted 工作和保留的 CID-NL 執行 adapter。Peak Detection 負責物理觀察與峰證據。

discovery/ · extraction/ · peak_detection/

跨樣本與輸出

Alignment 接手群組、修復組合及格值決策。Output 只渲染已完成結果，不再讀 RAW 或改選峰。

alignment/ · output/

機械工作與檢視

Execution Engine 管分區排程與暫存；runtime owner 管一次 attempt 的生命週期。Inspector 從完成證據做只讀報告。

execution/ · execution/attempt.py · xic_inspector/
依賴方向

資料入口、RAW/CSV adapter、GUI、CLI 與 renderer 可以往內使用 domain owner。Domain 演算法只依賴資料結構、型別化設定與小型模型；不反向匯入 GUI、RAW adapter、workbook、process backend 或報告 renderer。

Inspector 在流程末端

Inspector 讀取完成證據的只讀介面，來源 adapter 解讀方法專屬欄位；選擇和畫面維持方法中立。科學核心不呼叫 Inspector，Inspector 也不回寫 Matrix。

02 · 一次執行

一次 attempt，要有開始也要有收尾

Runtime 已接入 Targeted、Untargeted 與 GUI pipeline worker，管理一次 ProcessingAttempt 的工作與收尾。它不解讀 RAW 訊號，也不決定哪個峰或 Matrix 值應被採用。正式契約另包含尚未實作的設計，不能把整份契約當成可用功能清單。

最小狀態

  • queued · 排隊
  • running · 執行
  • terminal · 結束
  1. 1

    先確認這次必做什麼

    上游 owner 給 attempt 身分與封閉的 work manifest。若必要工作不完整、重複或未經確認，preflight 直接走 failed 收尾，不會假裝已開始或派出 worker。

  2. 2

    排工作，也先登記資源

    每個 work unit 排到 serial 或 process worker；RAW session 等資源在開啟前先登記。每單位的完成、失敗，以及資源開啟與清理，都留下對應記錄。

  3. 3

    取消或失敗不能變成科學上的「沒有」

    接受取消後停止安排新工作，處理在途工作並清理資源。Worker 消失或清理狀態不明要如實記 failed/unknown；先完成的暫存檔也不因此變成可交付結果。

  4. 4

    確認終局，再處置暫存

    所有必做單位和保留資源都收束後，runtime 提出結局；持久終局確認才正式提交 outcome。成功的暫存只「交給 owner 檢查」，失敗或取消的暫存留作診斷並隔離。

  • succeeded必做工作和收尾都成功，仍須由科學與 writer owner 決定產出。
  • failed工作、worker、完整性或清理失敗；不把缺的觀察推成零。
  • cancelled取消在終局決定前被接受，且沒有優先的失敗。

重跑與續跑不同

目前未提供沿用先前工作結果的 retry / resume。重新執行不等於接續失敗工作。Untargeted 可重用通過來源與查詢驗證的 acquisition cache，但會重新做科學決策。

量的是執行成本

timing 記錄已觀察到的 RAW 開啟、查詢及執行成本；未觀察到的數值維持 unavailable。這些記錄不評分證據品質。

目前的證據邊界：正式執行契約記載，整合證據尚未超過 diagnostic_only。這裡解釋契約規定的生命週期，不宣稱 Targeted、Alignment 或所有入口已通過產品整合驗證。

03 · 檢視邊界

保存值、取得曲線、畫面檢視是不同責任

日常閱讀結果由操作指南負責；維護實作時則要分清楚：來源 adapter 解讀保存證據，工作台 acquisition 按需取得 RAW 曲線，Inspector 的選擇與 renderer 呈現結果。

來源與保存值

工作台可開 Targeted XLSX 與完成的 CID-NL 結果。診斷 curve-bundle 是另一種來源，不代表相應方法已取得產品輸出支援。

曲線取得

需要 RAW 曲線時由工作台 acquisition 處理。不能因檢閱介面要求曲線，就讓 renderer 重選峰、重做科學決策或改格值。

離線報告

自包含 HTML 保存選定的曲線與記錄，供離線檢閱；它不回寫原始結果，也不是方法 activation 或 publication 的授權。

檢閱能做與不能做什麼查 Workbench and review；命令參數查各命令的 --help。一般使用者回 結果使用路徑。

這頁是人類閱讀導覽。正式 owner 仍是 docs/architecture-contract.md（模組責任與依賴）、docs/product/workbench.md（只讀檢視）。精確 API、欄位與實際能力以 owner 文件及現行程式為準。
