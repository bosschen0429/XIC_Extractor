從候選到定量矩陣

一個樣本裡看到訊號，還不能直接說它是跨樣本同一個峰，也不能把面積寫進矩陣。沿著一個「某樣本缺格」例子，看每一步回答什麼問題。

跟著這個例子讀

樣本 A、B 有相近的候選峰；樣本 C 的同一列目前沒有可用數值。問題不是立刻補一個面積，而是先確認 A、B 是否屬於同一個跨樣本群組，再問 C 能否依該群組脈絡找回可信的本地觀察。

樣本內候選→峰假說→跨樣本群組→必要時回填→格值決策→矩陣
01

Discovery：先找樣本內候選

Discovery 依方法指定的證據找候選，交出可檢視的觀察與峰假說。它負責「值得往下查什麼」，不決定跨樣本身份或最後數值。

方法可以不同，交接方式相同

CID-NL 可由中性流失等 MS2 線索出發；HCD-PI、Delta Mass 等方法讀取自己的證據。下游接收帶來源的觀察與假說，而不必為每種方法重建 Alignment 和 Backfill 流程。

例子：A 有候選，還不是「同一列」

A 的 MS1 trace 與種子證據支持一個本地峰，Discovery 會保留候選與 review 資訊。即使多個候選共用同一個樣本內峰錨點，那個標籤也不是 A、B、C 的跨樣本群組身份。

正式產品 owner：docs/product/discovery.md。候選狀態、方法證據、輸出和交接契約以該文件為準。

02

峰與定量脈絡：範圍要剛好

候選提出的短區間可能切到真實峰的兩側；整個搜尋窗又可能太寬。定量脈絡圍繞選定峰的 apex／假說，供邊界和積分判斷使用。

三個範圍，三種用途

搜尋窗用來找可能訊號；候選區間是峰提案；定量脈絡則是觀察峰形與計算面積所需的 trace 範圍。候選邊界若切掉峰翼，可在設定的 RT 限制內有限擴張。

例子：不能把整段雜訊都積進去

A 的候選左翼被截短時，系統可查看較完整的局部 trace。波形、局部極小值或形態特徵都是提案和審查證據；任何一項都不能暗中替代最後的峰選擇與面積決策。

正式產品 owner：docs/product/quantitation-context.md。邊界擴張、形態證據與面積影響的限制以該文件為準。

03

Alignment：判斷跨樣本是否對得上

Alignment 接收各樣本已帶來源的觀察和假說，建立或評估跨樣本對應。樣本內候選不是跨樣本群組的真值。

CrossSample 管身份

CrossSample 決定群組、成員、群組狀態及分裂／合併沿革。預測位置不取代本地量測；跨樣本對應仍須依共同證據判斷。

例子：A、B 接近，仍須過硬條件

A、B 的 RT 接近可支持比較，卻不能掩蓋不同峰、身份衝突或同一樣本多峰的歧義。群組關係關閉後，流程才把結果交給 Targeted 或 Untargeted 的列／格投影。

正式產品 owner：Alignment 說明跨樣本對應；群組身份與成員、結果交接由各自文件維護。

04

共享處理核心：同一套科學責任

Targeted 已知要找哪些 Target，Untargeted 從證據形成群組；兩者共用候選後的科學責任，再由各自的投影決定列、檢視與輸出樣式。

入口約束不等於觀察結果

Targeted 的目標清單限制搜尋並固定輸出列，但不能證明某樣本真的有峰。Untargeted 搜尋設定的證據空間，從關閉的 CrossSample 群組取得列身份。兩個入口都要走觀察、群組、可選修復與格值決策。

每個 owner 只回答自己的問題

Discovery 產生候選；CrossSample 管群組；ObservationRevisit 修一個不完整的觀察；Backfill 重訪缺格；ProductionCellDecision 選數值或不寫。結果關閉後，writer 只呈現已完成的決策，不重新讀 RAW 或重做科學判斷。

正式產品 owner：docs/product/shared-processing-kernel.md。介面、生命周期與 Targeted／Untargeted 責任邊界以該文件為準。

05

Backfill（回填）：有脈絡才重訪缺格

Backfill 是有限、依證據的本地重訪。已有直接觀察的格子可能不需要重訪；證據不足也可以保留未修復的理由。

例子：C 的缺格

若 A、B 提供已由 owner 支持的群組脈絡，C 可以依那個脈絡檢查本地訊號。找到峰也只是新增或修復一個觀察；還要另外判斷它是否屬於群組、是否可量化，以及能否寫出數值。

回填不是插值

Backfill 不從 A、B 的面積猜 C 的數字，也不能從零建立 Target／群組。它回傳可追溯的 ObservationRevisit 決定或明確的不修復結果；不直接給群組成員資格、選定數值或 writer 權限。

正式產品 owner：docs/product/backfill.md。重訪資格、來源證據、修復結果與套用邊界以該文件為準。

06

證據與決策：先過門檻，再比較分數

觀察證據、排序分數與產品決策是三件事。高分只能在可比較的候選之間排序，不能跳過缺少必要證據、錯峰衝突或來源不明等硬阻擋。

一個可解釋的決策順序

先說正在決定哪個群組或格子；列出必要的 trace、峰、來源等證據；檢查衝突與歧義；最後才用支持事實和排序解決仍可比較的候選。Targeted 與 Untargeted 各自決定列、計數、理由與檢視路由。

例子：C 找到峰也可能不寫

C 的 Backfill observation 若與群組身份不符，或積分不可用，格值可以明確停在 no-write。投影先建立列與格的 subject；ProductionCellDecision 再決定數值或不寫；同一投影最後處理列納入與理由。

正式產品 owner：docs/product/decision-policy.md。證據語義、硬門檻、排序與工作模式決策以該文件為準。

07

Quant Matrix：完成決策後的數值格子

Quant Matrix 是面向分析者的最終數值網格。主矩陣保持清楚的列與樣本結構；來源、身份和審查細節放在伴隨的 sidecar 或 review 表面。

每格有來源，也有不寫的可能

直接觀察與修復觀察是不同證據狀態。格值 owner 依已關閉的觀察決定最後數值或 typed no-write；投影決定這列和這格是否納入，授權 writer 再將結果呈現為矩陣。

例子：C 不會自動變成補上的數字

C 的 Backfill review 行即使看起來有面積，也還不是主矩陣格值。只有在對應的產品權限與已完成的格值決策允許時，版本化矩陣才可收下它；審查圖和診斷表不能自行授權寫入。

正式產品 owner：docs/product/quant-matrix.md。矩陣形狀、數值／sidecar 分工及寫入授權以該文件為準。

08

詞彙速查：別把相近名稱當同一件事

這些詞在流程中各有位置。尤其「候選」「群組」「修復觀察」「格值」不能互換。

XIC / Trace
指定 m/z 範圍內，訊號強度隨保留時間變化的曲線。
PeakHypothesis
提出某個峰的身份、RT 範圍和積分依據；被選中也不等於有寫入權限。
CrossSample
跨樣本群組、成員與身份的科學 owner。
ObservationRevisit
一個已有脈絡的本地觀察的修復決定；不等於插值或最後格值。
ProductionCellDecision
對一個明確 Target／群組格子，獨立選定數值或 no-write 的 owner。

正式詞彙 owner：docs/product/domain-glossary.md。完整術語、Targeted／Untargeted 與產品權限定義以該文件為準。
